Adds repeating tasks (#5119): the `task_series` table, `tasks.series_id` and `tasks.occurrence_date` with a unique key on the pair, and three service-role functions (`create_task_series`, `materialize_task_series_copy`, and the shared `insert_task_series_copy`).

## Promotion

- **Purpose**: a task can repeat on a schedule. A series holds the template and the rule; each copy is an ordinary `tasks` row, and only the next upcoming copy exists. The API's 5-minute sweep makes the next copy once the latest one is due. Existing tasks get null in both new columns and behave as before.
- **Checks**:
  - `select count(*) from public.task_series;` returns 0 right after promotion.
  - `select conname from pg_constraint where conname = 'tasks_series_occurrence_key';` returns one row.
  - `select proname from pg_proc where proname in ('create_task_series', 'materialize_task_series_copy', 'insert_task_series_copy');` returns three rows.
  - `select has_function_privilege('authenticated', 'public.create_task_series(uuid, uuid, text, text, uuid, int, text, text[], time, text, date, timestamptz, timestamptz, date)', 'execute');` returns false.
- **Promoter notes**: additive, with no data written. Promote before the API that calls the functions; an older API never reads the new columns, so the order only matters in that direction.

## Rollback

Worth it only if the migration itself breaks something. Dropping the table deletes every series, though copies already made stay as ordinary tasks (their `series_id` is dropped with the column). Run as a forward migration after the API that uses it has been rolled back ([playbook](../../db-rollback-playbook.md#decision-matrix)).

```sql
drop function if exists public.materialize_task_series_copy(uuid, date, timestamptz, date, timestamptz, timestamptz, date, boolean);
drop function if exists public.create_task_series(uuid, uuid, text, text, uuid, int, text, text[], time, text, date, timestamptz, timestamptz, date);
drop function if exists public.insert_task_series_copy(public.task_series, date, timestamptz);
alter table public.tasks drop constraint if exists tasks_series_occurrence_key;
alter table public.tasks drop column if exists occurrence_date;
alter table public.tasks drop column if exists series_id;
drop table if exists public.task_series;
```
