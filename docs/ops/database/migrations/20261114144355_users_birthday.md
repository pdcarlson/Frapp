Adds a member's birthday to `users` (#4959): `birthday_month`, `birthday_day`, an optional `birthday_year`, and `birthday_visibility` (`'nobody'` by default, or `'chapter'`), plus a trigger that clears them when account deletion tombstones the row.

## Promotion

- **Purpose**: four nullable-or-defaulted columns on `users`, two check constraints (`users_birthday_valid`: month and day together, a real day in the month, a year in 1900-2100 and 29 February only in a leap year when a year is given; `users_birthday_visibility_valid`), and a `before insert or update` trigger, `users_clear_birthday_on_tombstone`, that nulls the birthday and sets the visibility back to `'nobody'` on any write to a row with `deleted_at` set. `anonymize_user` is not redefined: its tombstone write fires the trigger.
- **Checks**:
  - `select count(*) from users where birthday_month is not null;` returns 0 right after the push.
  - `select count(*) from users where birthday_visibility <> 'nobody';` returns 0.
  - `select tgname from pg_trigger where tgname = 'users_clear_birthday_on_tombstone';` returns one row.
  - `select conname from pg_constraint where conname in ('users_birthday_valid', 'users_birthday_visibility_valid');` returns both.
- **Promoter notes**: no backfill and no data written; the default fills the visibility column in place. Apply it before the API that reads and writes the columns. The API serving now selects `users` with `*` and ignores the extra columns, so the order is safe. Nothing is done by hand.

## Rollback

Worth it only if the trigger faults writes to `users`. Revert the API first, so nothing writes the columns. Then run a forward migration. Dropping the columns loses every birthday members entered.

```sql
drop trigger if exists users_clear_birthday_on_tombstone on public.users;
drop function if exists public.users_clear_birthday_on_tombstone();
alter table public.users
  drop constraint if exists users_birthday_valid,
  drop constraint if exists users_birthday_visibility_valid,
  drop column if exists birthday_month,
  drop column if exists birthday_day,
  drop column if exists birthday_year,
  drop column if exists birthday_visibility;
```
