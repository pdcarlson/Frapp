# 20261120222543_gif_favorites.sql

Adds `gif_favorites`, each member's starred GIFs for the chat picker's Favorites tab, and purges them on account deletion (#5772).

## Promotion

- **Purpose**: a new table, one row per member per starred GIF (unique on member, provider and GIF id), with RLS on and no policies, read only by the API's service-role client. `anonymize_user` is redefined in full with one added delete of the member's favorites.
- **Checks**: `select count(*) from gif_favorites;` returns 0 right after the push. `select prosrc like '%delete from gif_favorites%' from pg_proc where proname = 'anonymize_user';` returns true.
- **Promoter notes**: push before the API that reads it; the API's Favorites routes 500 until the table exists, while search, trending and sends are unaffected. Writes no data.

## Rollback

Worth reverting only if the table itself causes trouble; the API routes that use it would have to be reverted first. Forward migration:

```sql
drop table if exists public.gif_favorites;
-- and redefine anonymize_user from 20261118173946_activity_layouts.sql, which lacks the delete
```
