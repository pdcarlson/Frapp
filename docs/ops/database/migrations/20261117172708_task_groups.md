Adds tasks for everyone (#4295 step 3): the `task_groups` table, `tasks.group_id` with a partial index, and the service-role function `create_task_group`, which writes a group, one copy per member and each copy's checklist in one transaction.

## Promotion

- **Purpose**: an officer can give a task to everyone. The group row names who it went to; each member's copy is an ordinary `tasks` row with `group_id` set, so it is marked done, confirmed and paid like any task. Existing tasks get null in the new column and behave as before.
- **Checks**:
  - `select count(*) from public.task_groups;` returns 0 right after promotion.
  - `select indexname from pg_indexes where indexname = 'idx_tasks_group';` returns one row.
  - `select has_function_privilege('authenticated', 'public.create_task_group(uuid, uuid, text, uuid[], text, text, date, timestamptz, int, text, text[])', 'execute');` returns false.
- **Promoter notes**: additive, with no data written. Promote before the API that calls the function; an older API never reads the new column, so the order only matters in that direction.

## Rollback

Worth it only if the migration itself breaks something. Dropping the table and column turns every copy already made into an ordinary task given to one member, which is what each copy is anyway. Run as a forward migration after the API that uses it has been rolled back ([playbook](../../db-rollback-playbook.md#decision-matrix)).

```sql
drop function if exists public.create_task_group(uuid, uuid, text, uuid[], text, text, date, timestamptz, int, text, text[]);
drop index if exists public.idx_tasks_group;
alter table public.tasks drop column if exists group_id;
drop table if exists public.task_groups;
```
