Adds majors as a third kind of automatic group (`chapter_groups.kind = 'major'`), one per distinct major a chapter's members have, so a major can be `@`-mentioned without a role per major ([#5778](https://github.com/frapplive/Frapp/issues/5778)).

## Promotion

- **Purpose**: `chapter_groups.major_key` (the folded major) and the `major` kind in its checks; a unique index per (chapter, major); `chapter_group_memberships` gains a branch reading `users.major`; triggers on `users.major` and `members` make and rename a major's row; `can_read_chat_channel` now ignores a major's group as it does a class year's. Backfills one row per (chapter, major) among existing members.
- **Checks**: `select count(*) from chapter_groups where kind = 'major';` matches `select count(*) from (select distinct m.chapter_id, chapter_major_key(u.major) from members m join users u on u.id = m.user_id where chapter_major_key(u.major) is not null) s;`, and `select tgname from pg_trigger where tgname in ('trg_users_sync_major_groups', 'trg_members_sync_major_group');` returns two rows.
- **Promoter notes**: push before the API that serves `kind: "major"` and `major_key`. An older API reads the new rows fine (it lists them as automatic groups and, through `findGroupIdsForUser`'s old `neq('kind','class_year')`, could count a major toward channel access only for a channel list naming one, which nothing can write before the new API refuses it; the database's own `can_read_chat_channel` already ignores majors). Writes data: the backfill.

## Rollback

Reverting is worth it only if the triggers misbehave on profile saves. A forward migration drops the triggers, the major rows (which takes any mention of them with it; nothing else names them, since no channel list can) and the column, and restores the view and `can_read_chat_channel` from `20261119210325`.

```sql
drop trigger if exists trg_users_sync_major_groups on public.users;
drop trigger if exists trg_members_sync_major_group on public.members;
drop function if exists public.users_sync_major_groups();
drop function if exists public.members_sync_major_group();
drop function if exists public.sync_chapter_major_groups(uuid[], text[]);
delete from public.chapter_groups where kind = 'major';
-- then: the view and can_read_chat_channel as 20261113040007 / 20261119210325
-- define them, the three checks as 20261113040007 defines them, and
alter table public.chapter_groups drop column if exists major_key;
drop function if exists public.chapter_major_key(text);
drop function if exists public.chapter_major_spelling(text);
```
