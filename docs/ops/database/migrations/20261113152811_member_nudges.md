Adds the two tables behind the member nudge card on Activity (#4781): `member_nudges` (one row per card) and `member_nudge_settings` (the member's own switch and quiet stretch), and makes `anonymize_user` delete both for a deleted account.

## Promotion

- **Purpose**: `member_nudges` holds the one card a member is shown at a time and the record of which tasks were already raised, so a dismissed card never comes back for the same task. A card's words are kept only while it shows. `member_nudge_settings` holds the member's switch and the quiet stretch "Fewer like this" starts. Both have RLS on and no policies: the API is the only reader and writer.
- **Checks**:
  - `select count(*) from member_nudges;` and `select count(*) from member_nudge_settings;` both run and return 0.
  - `select relrowsecurity from pg_class where relname in ('member_nudges', 'member_nudge_settings');` returns `t` twice.
  - `select prosrc like '%member_nudges%' from pg_proc where proname = 'anonymize_user';` returns `t`.
- **Promoter notes**: additive, writes no data, and safe to apply before the API that uses it. Nothing by hand.

## Rollback

Worth it only if the tables themselves cause a fault; the feature is off wherever `AI_ENABLED` is off. Revert the API first, then run a forward migration. Dropping the tables loses only cards and switches, which the next check rebuilds or defaults.

```sql
-- Redefine anonymize_user from 20261112165040_ai_consent.sql first (it must
-- stop naming the two tables), then:
drop table if exists public.member_nudges;
drop table if exists public.member_nudge_settings;
```
