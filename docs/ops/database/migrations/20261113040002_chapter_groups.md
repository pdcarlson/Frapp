Adds chapter groups (named sets of members with no permissions), lets channel who-can-see and who-can-post lists name them, and gives role tiers a ping switch ([#4076](https://github.com/pdcarlson/Frapp/issues/4076)).

## Promotion

- **Purpose**: new tables `chapter_groups` (manual groups, plus one row per pledge class and per graduation year a member has, kept by triggers) and `chapter_group_members` (manual groups' members only); view `chapter_group_memberships` (who is in each group now, computed live); function `set_chapter_group_members` (a manual group's list replaced all or none). `chat_access_list_valid` accepts `group:<uuid>`, a deleted group is stripped from every list, and `can_read_chat_channel` admits a member of a listed group. `role_tiers.mentionable` (default true). `groups:manage` is added to every tier holding `roles:manage` or `channels:manage`, and as an override to any role still holding either without it.
- **Checks**:
  - `select kind, count(*) from chapter_groups group by kind;` shows a `pledge_class` row per row of `chapter_pledge_classes` and a `class_year` row per distinct chapter and member graduation year.
  - `select count(*) from role_tiers where permissions && array['roles:manage','channels:manage'] and not ('groups:manage' = any(permissions));` returns 0.
  - `select count(*) from role_tiers where mentionable is not true;` returns 0.
- **Promoter notes**: push before the API deploys: the API reads `chapter_groups`, the view and `role_tiers.mentionable`, and an older API ignores all of them, so the old API keeps working on the new schema. Writes data: the automatic group backfill and the `groups:manage` backfill, both idempotent. Nothing by hand.

## Rollback

Worth it only if group reads break chat access for everyone; a group grants nothing, so a bad group row is fixed by deleting it, not by rolling back. A forward migration that drops the feature: first restore `chat_access_list_valid` and `can_read_chat_channel` to their definitions in `20261111233000_chat_channel_access_lists.sql` (copy them; a list still naming a group would then fail the check, so strip those entries first), then drop the rest. `groups:manage` and `role_tiers.mentionable` can stay: nothing reads them once the API is rolled back.

```sql
update public.chat_channels
   set who_can_see = nullif(array(select e from unnest(who_can_see) e where e not like 'group:%'), '{}'),
       who_can_post = nullif(array(select e from unnest(who_can_post) e where e not like 'group:%'), '{}')
 where array_to_string(who_can_see, ',') like '%group:%'
    or array_to_string(who_can_post, ',') like '%group:%';
-- (the same for chat_channel_categories' lists)
-- then: chat_access_list_valid and can_read_chat_channel as in 20261111233000
drop trigger if exists trg_chapter_pledge_classes_sync_group on public.chapter_pledge_classes;
drop trigger if exists trg_users_ensure_class_year_groups on public.users;
drop trigger if exists trg_members_ensure_class_year_group on public.members;
drop function if exists public.chapter_pledge_classes_sync_group();
drop function if exists public.users_ensure_class_year_groups();
drop function if exists public.members_ensure_class_year_group();
drop function if exists public.ensure_chapter_class_year_groups(uuid, uuid);
drop function if exists public.chapter_class_year_group_name(integer);
drop view if exists public.chapter_group_memberships;
drop function if exists public.set_chapter_group_members(uuid, uuid, uuid[]);
drop table if exists public.chapter_group_members;
drop table if exists public.chapter_groups;
```
