## 6. Where rigidity is hurting

The docs are genuinely good, above average for a repo this age. The failure mode isn't sloppiness — every incident produces a rule, no process removes one, and rules get written for judgment calls that didn't need them.

The docs-sync mandate manufactures noise: for a dependency bump, "no documentation changed" is the honest answer, but the gate makes that unrepresentable, so output gets written just to satisfy the check — and this is exactly how check-our-docs itself got left out of the skills table (PR #973 satisfied the gate by editing six other docs and missed the one that needed it). The gate measures motion, not correctness.

Rules that would've been followed anyway sit right next to load-bearing ones (the React pin, the Expo lockfile rule, service_role bypassing RLS) — mixing them trains the reader to skim, which is when the important ones get missed.

Places the agent has silently picked a side: spec-first vs code-first (follows AGENTS.md, nothing tells it to); which brand doc wins (positioning.md prints the losing values then disclaims itself — a fresh agent landing on positioning.md first gets a confidently wrong answer); how much sub-agent delegation is appropriate (both readings defensible, nothing adjudicates); whether "chunk 10a-10h" labels still mean anything (treated as dead, no way to be sure).

Over-specification with a measurable price: next.md (641 lines for "claim an issue, do it, ship it" — its own frontmatter admits "policy lives in GITHUB_PM.md; this file is procedure; where they disagree, the doc wins and this file is the bug" — a documented split-brain); the "filing follow-up work" section (62 lines/26% of AGENTS.md, mostly formatting rules that belong in a skill, not the every-session file); the /code-review rule (3-4 copies across AGENTS.md, the hook header, a runbook, and a struck-through self-correcting sentence in an ADR amendment); the routine ownership boundary (5 copies).

What's genuinely good, don't lose it: the FROZEN banners on two legacy-surface READMEs (stale docs made *safe* instead of deleted — best pattern in the tree); the mock quarantine in ai.md; the amendment-with-correction pattern in ADR-14 ("the premise was measured wrong; the conclusion still holds, for different reasons"); the evidence-keyed review gate; the React pin gotcha (explains the failure, why npm accepts the bad state silently, that only a device boot catches it, that the pin moves with Expo bumps — hold other entries to this standard).
