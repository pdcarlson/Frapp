# Research: AI meeting recaps & AI podcast

Bottom line: both features are nearly free to run at chapter scale (tens of dollars a month even across 200 chapters) — cost is not the constraint, input source and build complexity are.

Recaps: build on typed meeting minutes (chapters already produce these), not audio recording+transcription. Recording adds real problems: 11 US states require all-party consent (CA, CT, FL, IL, MD, MA, MT, NH, PA, WA — flag per chapter location, don't try to solve centrally), it's socially awkward, and transcription accuracy drops hard in multi-speaker room settings (diarization error ~26-27%). Minutes-based summarization costs ~$0.0007/meeting; keep audio upload as an optional later add-on.

Action items: Otter/Fireflies/Fathom/Read.ai all auto-detect and assign action items, but accuracy drops to ~75% in group calls and tools themselves recommend a human review step. Treat extracted action items as drafts requiring confirmation before any reminder fires — don't auto-fire notifications off this, ties into the separate notifications feature.

AI podcast: NotebookLM's Audio Overview = LLM writes a two-host script, then multi-speaker TTS renders it (Google's internal SoundStorm stack, not an API you can call). Key finding: TTS is billed per character regardless of voice count, so two-host format costs the same as single-voice — the two-host format is a complexity/quality choice, not a cost one. NotebookLM itself now ships a single-voice "Brief" format alongside the two-host "Deep Dive," suggesting single-voice covers most use cases. Recommend starting with single-voice narration of the text recap (OpenAI tts-1 ~$0.06/5-min episode) rather than a two-host podcast (ElevenLabs, ~$0.20-0.45/episode) — defer two-host as a possible later delight feature, not a first build.

Reference tools: Podcastfy (open source, Gemini script + OpenAI TTS) is close to the exact stack Signet would assemble if this gets built.

Build order (simplest to hardest): (1) text recap from typed minutes, (2) draft action items with confirm step, (3) optional recording+transcription path, (4) single-voice audio narration, (5) two-host podcast — last and most deferrable.
