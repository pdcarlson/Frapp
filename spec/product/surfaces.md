# Surfaces

## Landing — frapp.live

A standalone marketing site (`apps/landing`). Deployed independently from the app.

- **Chat first, and the page says so.** The hero leads on running the chapter where it already talks; the two proof sections are chat and events with check-in. Backwork and points are named on the Chapter Pro list rather than presented as co-equal headline features; study hours is named on neither tier in [`positioning.md`](positioning.md), so the page omits it rather than guessing. The composition is [`spec/ui/landing/README.md`](../ui/landing/README.md) § Section inventory.
- Pricing: **both tiers are what the page owes**, and both now render ([#2367](https://github.com/pdcarlson/Frapp/issues/2367), decision D3). The free tier — unlimited chat, members and chapters, no card — is the wedge, and Chapter Pro is a flat monthly per-chapter plan. Amounts and what each tier gates are [`positioning.md`](positioning.md), which is canonical; the page sells them and does not set them. One button, on Free: both cards resolve to `/sign-up` because no checkout deep link exists, and the trial opens at in-app checkout rather than from this page.
- **No unverified metrics and no testimonials.** The stats row and the three unsourced testimonial quotes were deleted with the page rebuild ([#2367](https://github.com/pdcarlson/Frapp/issues/2367)), and neither returns. The only figures on the page are the commitments [`positioning.md`](positioning.md#paid-tier-chapter-pro) records: the two tier prices and the trial's length and first-charge day. Any figure or quote added later **must** reflect verified metrics and real customers — a name, a chapter and consent — or be clearly labeled as illustrative until validated (see [`spec/ui/brand-identity.md`](../ui/brand-identity.md)). The two product frames carry invented demo data and each says so in a caption.
- CTA: "Get started" (redirects to `app.frapp.live/sign-up`) and "Sign in" (redirects to `app.frapp.live/sign-in`); sentence case is decision D5. The analytics ids are unchanged — the sign-in control still reports `log-in` so one PostHog funnel survives the relabel. These must match the web app's actual auth routes — there is no `/signup` or `/login` route. An empty, whitespace, or scheme-less `NEXT_PUBLIC_APP_URL` falls back to that origin at request time rather than 500ing `/` ([#1777](https://github.com/pdcarlson/Frapp/issues/1777)); operator copy lives in [`docs/internal/environment/ENV_REFERENCE.md`](../../docs/internal/environment/ENV_REFERENCE.md).
- `/join` (including `?token=` / `?invite=` / `?code=`) permanently redirects to the web app's `/join` on `NEXT_PUBLIC_APP_URL` (production default `app.frapp.live`) with the query string intact. The redirect base must be `https:` — a public `http:` base throws rather than putting the invite token on the wire (`assertHttpsJoinOrigin` in `@repo/validation`, the same helper `mintJoinUrl` uses for web/API/mobile minting). Loopback `http:` (`localhost`, `127.0.0.1`, `::1`) is allowed so local Infisical `APP_URL` still works. A Vercel production deploy (`VERCEL_ENV=production`) also requires that base's origin to be `https://app.frapp.live` at request time and at `next build`; staging deploys this repo as `preview` and may still forward to `app.staging.frapp.live`. The marketing site has no redeem UI; officers still mint `app.frapp.live/join?token=…`. `/join` is not in the landing sitemap.
- **Legal pages:** Terms of Service (`/terms`), Privacy Policy (`/privacy`), FERPA Notice (`/ferpa`). Linked from the site footer.

## Web App — app.frapp.live

The admin console (`apps/web`). Next.js App Router, Tailwind, ShadCN UI. A Vercel production deploy (`VERCEL_ENV=production`) fails `next build` unless `NEXT_PUBLIC_API_URL` is origin `https://api.frapp.live`, `NEXT_PUBLIC_SUPABASE_URL` is the `frapp-prod` project, and `NEXT_PUBLIC_SUPABASE_ANON_KEY` is an anon key for that same project. Staging deploys this repo as `preview` and is not fenced. The build gate and operator copy live in [`docs/internal/environment/ENV_REFERENCE.md`](../../docs/internal/environment/ENV_REFERENCE.md).

**Screens:**

- **Onboarding Tutorial** — Guided walkthrough on first sign-in, skippable and revisitable from settings (`components/onboarding/onboarding-tutorial.tsx`). The slides and their order are owned by [`spec/behavior/onboarding.md`](../behavior/onboarding.md) § Onboarding Tutorial. There is no mobile equivalent — mobile's first-run screen is s03.
- **Chat (member view)** — The post-sign-in landing (`/chat`) and the app's primary surface: channel list by category, DMs, real-time messaging with reactions, replies, uploads, and inline rich-message cards. There is no standalone dashboard home — `/dashboard` redirects here, and `/` does too once a Supabase session exists (signed-out visitors get the landing page). Chapter health at a glance is re-homed as an inline chat artifact, the pulse card — see [`spec/behavior/chat/catch-up.md`](../behavior/chat/catch-up.md). Subscription status lives in the dashboard shell and the Billing screen below.
- **Members** — Searchable member directory: a dense row per member (name, role, join date, email, points) opening a detail sheet, with an Alumni tab beside it. Role assignment, invite generation, remove/deactivate. (Web dropped the profile-card grid in the greenfield Directory lane, [#2146](https://github.com/pdcarlson/Frapp/issues/2146); the mobile row below still reads as its own surface.)
- **Roles & Permissions** — View/create/edit roles with open-ended permissions; assign display order and color; manage system role permissions. Presidency transfer UI.
- **Billing** — Subscription status, invoices, payment history (Stripe Customer Portal link).
- **Financial Invoices** — Create/send invoices to members (dues); track payment status; overdue alerts.
- **Events** — Create/edit events with configurable point values, mandatory flags, location, and recurrence rules. View attendance per event. Calendar view.
- **Backwork Admin** — Browse uploaded resources with rich filters (department, course, professor, semester, year, assignment type, document variant). Manage departments and professors. View redacted vs. original indicators.
- **Points Ledger** — Leaderboard (all-time, semester, month). Full transaction log with audit trail (who adjusted, reason). Manual point adjustments. Anomaly flagging and audit tab (chapter-wide list via `GET /v1/points/transactions`, gated by `points:view_all`; see [`spec/behavior/points.md`](../behavior/points.md)).
- **Study Geofences** — Draw/manage geofence polygons for study locations. Configure reward rates and minimum session lengths.
- **Chat (admin view)** — Channel management: create/edit/delete channels, organize into categories, set permission requirements. Manage pinned messages. View #announcements posting.
- **Polls** — Chapter-wide poll list with aggregate tallies on the web app (`GET /v1/polls`, gated by `polls:view_all`; see [`spec/behavior/polls.md`](../behavior/polls.md) and [`spec/ui/web-dashboard/README.md`](../ui/web-dashboard/README.md)). Create polls and vote in channels per chat permissions.
- **Tasks** — Create/assign tasks to members. Track status (TODO, IN_PROGRESS, COMPLETED, OVERDUE). Confirm completion and award points. Filter by assignee, status, due date.
- **Service Hours** — Admin review queue for submitted service entries. Approve/reject with optional comments. Chapter-wide service report. Configure points-per-hour rate.
- **Chapter Documents** — Upload, organize, and manage chapter files (bylaws, constitutions, agendas). Flat folder structure. Reads are gated on `members:view` — every seeded role holds it or clears it via `*`, so in practice every member can view and download, but a custom role without it cannot; [`../behavior/chapter-docs.md`](../behavior/chapter-docs.md) owns the gate.
- **Reports & Export** — Generate and download CSV/PDF reports: attendance, points, member roster, service hours. Select date range and scope. Branded PDF templates with chapter logo.
- **Settings** — Chapter profile (name, university). Chapter branding (upload logo, set accent color). Default role configuration. Notification defaults. Semester rollover action ("Start New Semester"). Danger zone (cancel subscription, transfer presidency).

## Mobile App (iOS + Android)

The member experience (`apps/mobile`). Expo with Expo Router.

**Screens:**

- **First-run (s03)** — Mobile's onboarding surface (`app/(auth)/welcome.tsx`), reached when the auth gate reads `has_completed_onboarding` as false. It is a single first-run screen, **not** the web modal slideshow; both are owned by [`spec/behavior/onboarding.md`](../behavior/onboarding.md) § Onboarding Tutorial, which is where the per-surface split is stated.
- **Activity Feed** — **specified, no surface today**: mobile's `(tabs)/index.tsx` is `ChatHomeScreen`, and on web `/dashboard` redirects to `/chat` unconditionally while `/` does so once a session exists. The item set is owned by [`../behavior/activity-feed.md`](../behavior/activity-feed.md).
- **Chat** — Channel list organized by categories (respecting permission gates). Real-time messaging with reactions, replies, typing indicators, online presence. Full-text search within and across channels. **Corrected 2026-09-21 against the binary:** there is no separate Direct Messages *tab* — DMs render as a `DIRECT` section in the channel list that is hidden entirely when empty — no pinned-messages panel (`ChatChannel` carries no pin field, per [`spec/ui/mobile/screens.md`](../ui/mobile/screens.md) s04), and, until #2464 (2026-09-22), no image **upload** path on iOS. The composer now sends a photo picked from the library (`lib/chat/attachment-upload.ts`). Non-image files still arrive only from the web dashboard, and `message-attachments.tsx` renders both.
- **Backwork** — **Not on mobile for the beta (owner decision 2026-09-23, [#2258](https://github.com/pdcarlson/Frapp/issues/2258)); the web dashboard keeps it.** There is no Backwork route under `apps/mobile/app/`, and since #2302 no user-facing copy mentions it either: the create-chapter sentence that did was removed, and only code comments remain. The upload half has no surface either. `expo-image-picker` is a dependency again since #2464, but it picks photos, not documents; a document picker is not a dependency, and `package.json` is frozen (#937), so "select file" still needs that decision first. The browse/download/search item set below describes the **web dashboard** surface; bringing it to mobile would reopen #2258: Browse by department, course, professor, semester/year, assignment type, document variant, and tags. Upload flow: select file, fill metadata (all optional), optionally redact (v2, unbuilt; the FERPA notice stopped implying it on 2026-09-22, #2262). Download with signed URL. Full-text search.
- **Events** — Upcoming events list. Self-service check-in during the event window. "Add to Calendar" generating an `.ics`. **Corrected 2026-09-21:** there is **no calendar view** (the screen is a flat list), **no past-events-with-attendance** — `lib/events/select.ts` drops finished events deliberately and notes "Attendance history is a reports surface" — and **no recurring-event indicator**: `recurrence_rule` is read only by the calendar export, never rendered as a badge.
- **Study Hours** — Pick a zone from a list (`components/study/zone-picker-sheet.tsx`), start a session, and get a study-mode screen with a large timer, location status and progress toward the next point. Foreground enforcement with pause/resume. Stop session. Session history with points earned. **Corrected 2026-09-21:** there is **no map and no polygon overlay** — `apps/mobile` has no mapping dependency, and `lib/events/select.ts` records that the polygon "is never needed on the client" because the server re-checks; adding one would mean adding a map library to a frozen `package.json`. There is **no streak indicator** — the string appears in no mobile component.
- **My Points** — **No such mobile screen today (corrected 2026-09-21).** `(tabs)/points.tsx` and `(tabs)/points-details.tsx` were deleted; what survives is a "Semester points" / "House rank #N of M" tile on the Tasks tab (`components/tasks/points-summary-card.tsx`), whose denominator is members with points in the window, not chapter size. There is no mobile leaderboard list and no time-window selector — [`spec/ui/mobile/screens.md`](../ui/mobile/screens.md) records that no standalone leaderboard replaced the deleted one, by design. The leaderboard list is web-only. The balance and transaction items below remain specified.
- **Notifications** — In-app notification center with deep linking. Mark as read. Quiet hours configuration (on the Preferences tab). **Corrected 2026-09-21:** there is **no category filter control** — the category is a derived per-row label only, and `notifications.tsx` records that "a notification row does not store its category".
- **Profile** — Display name, avatar, points/service stats, account details and bio. Read-only on mobile; the screen points to the web dashboard for editing. Push preferences, quiet hours and Sign out are on the Preferences tab, not here.
- **Member Directory** — Searchable list of chapter members with profile cards. Tap to view a profile. **No DM entry (corrected 2026-09-21):** `apps/mobile/components/directory/member-detail-sheet.tsx` carries a standing "No DM entry" note scoping it to #316, and `useGetOrCreateDm`'s only product consumer repo-wide is the web dashboard's member sheet. Nothing in the iOS app can start a DM; existing DMs are read and replied to normally.
- **Tasks** — View tasks assigned to the user. Update status (IN_PROGRESS, COMPLETED). See due dates, point rewards, and confirmation status. Plus the one officer affordance that ships on mobile (**added 2026-09-21**, it was missing): a `tasks:manage` holder gets a "New task" header action opening `components/tasks/new-task-sheet.tsx`, which assigns to any roster member. The board itself is assignee-filtered (`lib/tasks/board.ts`), and so is the Chat tab's UP NEXT strip — `GET /v1/tasks` widens for an admin, so a personally-framed surface must filter by assignee itself.
- **Service Hours** — Log service entries (duration and description) and view your own history with its approval status. **Corrected 2026-09-21 against the binary:** the date is **not** chosen — `service-hours.tsx` hardcodes `date: todayIsoDate(new Date())` and the sheet says "Dated today"; there is **no proof upload** (the screen's docblock records that the field is omitted rather than rendered dead, for want of a file picker, and [`spec/ui/mobile/screens.md`](../ui/mobile/screens.md) s20 agrees); and there is **no chapter service leaderboard** on mobile — the only `useLeaderboard` consumer is `tasks.tsx`, and it is the *points* leaderboard. Approval and the chapter-wide report are the web dashboard's (the § Web Dashboard row above).
- **Chapter Documents** — Browse and download chapter files organized by folder. Search by title.
- **Alumni Directory** — Searchable list of alumni members. Filter by graduation year, city, company. View alumni profile cards.
- **Polls** — Vote on active polls in a channel and view the tallies (`components/chat/poll-card.tsx`: question plus tappable options pre-vote, bar tallies after). **Corrected 2026-09-21: creation does not ship on mobile** — there is no poll composer, and `createPoll` has no consumer in `apps/mobile`. Worth stating rather than leaving as "(if permitted)", because `polls:create` **is** in the seeded Member role, so that phrasing read as shipped for everyone.

## Documentation (repo markdown today)

Developer documentation: canonical markdown in [`docs/guides/`](../../docs/guides/README.md) and product detail in **`spec/`**. There is **no** separate public docs website in the monorepo for now; contributors read on GitHub (or locally). A polished public docs site (and possibly changelog, feedback, etc.) is a **post-launch** candidate.

- Getting started and engineering guides: `docs/guides/`.
- Product behavior and architecture: `spec/`.
- Audience: contributors and operators; chapter-admin-facing help may grow separately.
