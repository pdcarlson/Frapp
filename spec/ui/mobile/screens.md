# Mobile Screen Inventory (s01–s23)

> The 23 locked Canvas screens mapped to expo-router paths, plus the pre-Signet screens they replace. The mapping is total: every current file under `apps/mobile/app` is accounted for.

Visual truth: [`../design-system/reference/canvas-screens.dc.html`](../design-system/reference/canvas-screens.dc.html). Screen ids (`s01`…`s23`) and Canvas labels below match that file's `data-screen-label` attributes exactly.

## Route conventions

- Routes live under `apps/mobile/app`. `(app)/` holds everything a member does inside a chapter: the four tabs in `(app)/(tabs)/`, and every other screen pushed on a stack above them ([`navigation.md` § Going back](navigation.md#going-back)). `(auth)/` holds everything before that point — which is **not** the same as "signed out": `chapter-picker` and s02/s03 are reached while authenticated. The group's gate keys on chapter context, not on session alone, so a member with no resolved chapter stays here (`apps/mobile/lib/auth-gate.ts` holds the single decision both layouts read).
- Routes not in the 4-tab bar live in `app/(app)/`, pushed on the stack over the tabs and reached by navigation only ([`navigation.md` § Going back](navigation.md#going-back)).
- **Filename contract:** `event-details.tsx` MUST never be renamed. `frapp://event-details` is baked into every `.ics` file members exported before the export was withdrawn (#3708), so renaming the route breaks calendar entries already sitting on members' devices. The whole contract (route, URL and `id` param) is in [`navigation.md` § Deep links](navigation.md#deep-links).
- All other renames land together in a single PR so typed routes never half-break — see [`navigation.md`](navigation.md).
- Bottom-sheet screens (marked *sheet* below) are `@gorhom/bottom-sheet` components hosted by a parent screen, not router routes — see [`patterns.md`](patterns.md). s17 is both: a sheet the tab bar's quick-actions host presents, and a route file the frozen tab layout's registration requires (see the status legend).

## Notes

- Every screen implements the skeleton/empty/error states family — rule stated once in [`README.md`](README.md), not per row. The shared pieces are in `apps/mobile/components/state-block.tsx`, built to [`../design-system/components.md`](../design-system/components.md) §10: each screen draws its own loading skeleton from them (`SkeletonRegion`, `SkeletonText`, and the row and card placeholders beside their components), and the generic `SkeletonLines` card is left only for states that are themselves one card, plus two list-shaped sheets still owed their own (member detail and blocked members, [#3522](https://github.com/pdcarlson/Frapp/issues/3522)). It adds a fourth member: a **"no chapter selected"** state, because a token with no `active_chapter_id` claim (no membership yet, or the hook disabled as incident mitigation) leaves every chapter-scoped query disabled and that is what a member actually sees. The screens predating it still carry their own inline loading/error blocks.
- **s17 has no mock.** Until 2026-11-12 Ask answered from a hand-written keyword table behind a build flag (`EXPO_PUBLIC_ASK_ENABLED`), with a note here on how that squared with the omit-don't-fake rule below. The note ended "the moment the flag can be turned on for a real chapter, that file must be gone rather than extended", and it is: the table, the flag and `app.config.js`'s production fence were deleted when Ask got a real API (#4415), and nothing on the phone answers from invented data.
- **Elements drawn in Canvas that have no backing data are omitted, not faked.** In this cluster: s16's "Join code" (chapters have no join code — joining runs through single-use, expiring invite tokens), s15's "96% attendance" and its Big brother row (its Pledge class row is drawn since #3939, and Phone since #3711), and s11's payment plan, payment-method sub-labels (`Visa ··4242`) and receipts-email line. - s16's drawn title is "Settings" while the route file is `preferences.tsx`.
