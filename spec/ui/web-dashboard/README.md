# UI/UX Specification: Web Dashboard (app.frapp.live)

> The chapter admin command center — secondary to chat in the chat-first product. Four structural facts the table alone does not carry:

- **Chat is an anchor, not a section.** It renders first with no heading, because it is where `/`, `/dashboard`, and the route-group index all land — it is the app's home rather than a member of any group.
- **A section heading hides with its items.** Section visibility is derived, never declared: `isNavItemVisible` (`apps/web/components/layout/protected-nav-item.tsx`) is exported so `dashboard-shell.tsx` can ask the same question the items do, and a section with zero surviving items renders nothing at all. That is the whole mechanism behind the Admin group being role-gated — every item in it carries a permission, so an ordinary member sees neither the rows nor the word "Admin". A future ungated item added there would silently un-gate the heading, which `protected-nav-item.test.tsx` pins against.
- **Settings is permission-gated now.** It reads `GET /chapters/:id/config`, which the API guards with `chapter-config:view`; an ungated entry point sent members without it to a screen that could not load, which is the fail-fast rule in [`../design-system/README.md`](../design-system/README.md) §5 inverted.
- **Profile left the nav** for the account menu (below). It is about the viewer, not the chapter, so it did not belong among chapter surfaces.

**Directory is one screen with two tabs.** `/members` hosts `?tab=members|alumni` (`apps/web/components/members/directory-page.tsx`), and `/alumni` redirects into `?tab=alumni`. Actives and alumni are one directory; asking a member to know which list a person is on before they can look them up was the defect. The redirect keeps existing links and bookmarks alive, the same shape `/roles` uses to reach Settings → Roles (role IA canon: [`spec/behavior/settings/customization.md`](../../behavior/settings/customization.md)). `nav-config.ts` remains the source of truth for what renders. Roadmap entries render soft-disabled with a `Soon` chip (`aria-disabled="true"` + `tabIndex={-1}`).

## Gating & routing semantics

- **Module gating is hide, not grey.** Each nav item carries a `module` field; `<ProtectedNavItem>` reads `useOrgConfig().isModuleEnabled(item.module)` and **hides** items whose module is disabled — never disabled-greyed. Permission gating and module gating coexist: an item shows only when the caller holds the permission *and* the module is enabled. Disabling a module from Settings → Modules immediately removes its sidebar item, strips its slash commands from the chat palette, and mutes its system channel; data is preserved and re-enabling restores everything ([`spec/behavior/settings/README.md`](../../behavior/settings/README.md)).
- **Default route.** Chat is the post-sign-in landing surface: `/` redirects to `/chat` once a Supabase session is present, `/dashboard` is a legacy alias that also redirects to `/chat`, and `app/(dashboard)/page.tsx` (the route-group index) redirects there as well so bookmarks and internal tooling always find a segment root. The standalone `/home` overview was removed in the chat-first rework. Users with zero permissions land on `/no-access`, which explains how to request a role without dumping them back to sign-in.
- **Unauthenticated deep links keep their destination.** [`apps/web/proxy.ts`](../../../apps/web/proxy.ts) guards every protected prefix: with no Supabase session it redirects to `/sign-in?redirectTo=<pathname + search>`, and once a session exists the same proxy returns the caller there instead of the `/chat` default. The value must start with `/` or it falls back to `/chat` — the open-redirect guard, applied in the proxy and again in `resolveRedirectPath` ([`apps/web/lib/auth/redirect.ts`](../../../apps/web/lib/auth/redirect.ts)) — and it survives the sign-in ↔ sign-up hop and is reused as the magic-link `emailRedirectTo`.
- **Web study pause is server-owned.** The `/study` timer calls `POST /v1/study-sessions/pause` when the tab is hidden (Page Visibility API) or manually paused, so the server stops crediting time and starts the grace clock; returning calls `/resume` with fresh coordinates, and overrunning the zone's `pause_grace_minutes` ends the session `PAUSED_EXPIRED`. Full rules: [`spec/behavior/study-sessions.md`](../../behavior/study-sessions.md). `/geofences` configures each zone's polygon, points rate, minimum session length, and pause grace.

## Responsive contract

Shell geometry as built. Source of truth: [`apps/web/components/layout/dashboard-shell.tsx`](../../../apps/web/components/layout/dashboard-shell.tsx) against stock Tailwind v3 breakpoints (`sm` 640px, `md` 768px, `lg` 1024px) — the shared preset ([`packages/theme/src/tailwind.config.ts`](../../../packages/theme/src/tailwind.config.ts)) extends colors, radii, and motion but never overrides `screens`.

| Viewport | Primary navigation | Content column |
| --- | --- | --- |
| ≥1024px (`lg`) | Fixed 288px (`w-72`) sidebar, always expanded, its own scroll region | Remaining width inside the shell cap |
| <1024px | Sidebar hidden; header hamburger opens a left slide-out Sheet (75% of viewport width, capped at 384px from 640px up) over a modal overlay | Full width |

- **Two states, not four.** The shell switches once, at `lg`. There is no collapsed icon-rail tier and no hover-expand sidebar; adding or removing a tier is a spec change, not a refactor.
- **The cap is on the shell, not the content.** `max-w-[1400px]` with `mx-auto` bounds sidebar and content together and centers them, so above 1400px the surface gains bare-background gutters. The content column carries no max-width of its own. Horizontal padding is `px-4` below 640px and `px-6` from 640px up, applied identically to the sticky 64px header and to `<main>`.
- **The drawer is the sidebar.** Both render the same section list, so every nav item and its permission and module gates reach the drawer automatically. Navigation MUST NOT be duplicated into a separate mobile list; the trigger keeps its "Open navigation menu" accessible name and the drawer keeps its labelled title and description. The account menu rides the same shared bottom region, so it reaches the drawer the same way.
- **The header collapses below `sm`.** The breadcrumb column is `min-w-0` and truncates; the search control goes icon-only; the page's primary action stands down (every one of those actions is also reachable inside the page). Without this the control row alone measured ~557px at a 375px viewport. Moving theme and sign-out into the account menu recovered most of the excess, and these three cover the rest. The collapse only takes effect if the **content column** is also `min-w-0` — see the floor rule below.
- **375px is the floor.** Every dashboard route MUST render without horizontal scroll down to 375px. Every route in `DASHBOARD_ROUTES` ([`apps/web/tests/visual/routes.ts`](../../../apps/web/tests/visual/routes.ts) — the count lives there, not here) holds it, and [`apps/web/tests/visual/responsive-floor.spec.ts`](../../../apps/web/tests/visual/responsive-floor.spec.ts) measures it — a plain `scrollWidth <= 375` assertion per route, no baseline. The **pre-auth** routes are measured too, by a second spec ([`pre-auth-floor.spec.ts`](../../../apps/web/tests/visual/pre-auth-floor.spec.ts)) in the same required job, because they need the opposite redirect assertion: the dashboard suite asserts a route did *not* land on `/sign-in`, which for `/sign-in` itself is backwards. Nineteen routes, plus one guard; `/join` is the gap, since its own session check redirects a sessionless harness away. Before #1142 nothing measured it at all, because the visual snapshot suite of the day pinned every shot to 1440×960 and could not see this class of defect. **It is meant to block.** #1152 split it out of the advisory `web-visual-regression` into its own `web-responsive-floor` job and listed that job in [`scripts/configure-branch-protection.mjs`](../../../scripts/configure-branch-protection.mjs); that snapshot job was advisory because baselines drift with Chromium, and the floor gate had inherited the exemption purely by sharing a directory with it despite storing no baseline and comparing no pixels. The snapshot job has since been deleted, so `test:floor` now runs the whole directory rather than a tagged slice of it. Whether the job is *live* on a branch depends on when an admin last ran `npm run configure:branch-protection` — read live state per [`GITHUB_BRANCH_PROTECTION_RUNBOOK.md`](../../../docs/internal/ops/GITHUB_BRANCH_PROTECTION_RUNBOOK.md#required-status-checks), not from this page. Either way, read a green board carefully: it does not on its own prove the floor held — see the coverage limits below.
- **What that gate does and does not cover.** It runs a sessionless harness — no active chapter — so on most dashboard routes `<main>` is a 160–256px empty-state card and the route's real content never mounts. The four pre-auth routes are the inversion of that limit and the reason they are worth measuring: signed out is not a degraded mode for a sign-in screen, it is the only mode, so there the harness renders exactly what a visitor sees. It therefore pins the **shell** on every route — which is what actually broke — and the page content only where the route renders it without a chapter (`/points` does). A populated table that overflows at 375px while its empty state does not would still pass. Signed-in coverage is not solved; do not read a green run as "this screen is responsive".
- **The content column MUST stay `min-w-0`.** It is a flex item, so its automatic minimum size is its min-content width: without the override it will not shrink below the widest unbreakable thing on the route, the header never gets a reason to collapse, and the page scrolls sideways. This is not a micro-optimisation — a missing `min-w-0` here was six of the seven routes reported in #1142 (`/documents` 426px, `/reports` 408, `/settings` 408, `/study` 392, `/service` 390, `/geofences` 383). It presents as per-route content overflow, and was filed that way, because page content is what supplies the min-content number; the shell measured clean on its own. Read a floor failure as a shell question first.
- **In-page columns collapse on their own breakpoint.** Chat stacks to one column below 768px and becomes a `260px / 1fr / 300px` grid at `md` and up ([`apps/web/components/chat/chat-shell.tsx`](../../../apps/web/components/chat/chat-shell.tsx)); its three panes are **not cards** — the thread sits on `--background` so the `--card` message bubbles read as the step above it, and the two rails take `--surface-1`, the ladder step the sidebar already uses (rationale: [`../design-system/components.md`](../design-system/components.md) §2); Settings is a wrapped horizontal tab row below 1024px and a 224px vertical rail at `lg` ([`apps/web/components/settings/settings-page.tsx`](../../../apps/web/components/settings/settings-page.tsx)). Both tiers count as impacted responsive behavior for those routes.

## Surviving data contracts

Per-screen truths that outlive the retired screen docs. Where a fact is canonical in `spec/behavior/`, the pointer is the fact — do not restate it here.

- **Global query defaults.** One browser-wide `QueryClient` ([`apps/web/lib/providers/query-provider.tsx`](../../../apps/web/lib/providers/query-provider.tsx)) defaults queries to `staleTime: 30_000`, `gcTime: 10 * 60_000`, `retry: 3`, `retryDelay: min(1000 * 2 ** attempt, 30_000)`, `refetchOnWindowFocus: true`, `refetchOnReconnect: "always"`, and mutations to `retry: 2` with the same backoff capped at 10s. Both retry policies are status-blind — no `networkMode` and no non-retryable-status predicate ship — so a 4xx is retried like a 5xx unless the caller sets its own `retry`; the one systematic status-driven behavior is the unauthenticated redirect under [Gating & routing semantics](#gating--routing-semantics). The chat message cache opts out with `staleTime: Infinity` because realtime, not polling, keeps it fresh That is also why chat resolves author and DM names from the cached chapter roster (`GET /v1/members/roster`) by `sender_id` instead of joining them onto the message; `spec/behavior/chat/README.md` owns that rule and the reasoning behind it.
- **Mutation optimism is opt-in, not the default.** The domain hooks in [`packages/hooks/src/`](../../../packages/hooks/src) are pessimistic — `mutationFn`, then `invalidateQueries` on success; the only `onMutate`/rollback paths that ship are the chat send ([`packages/chat-core/src/cache.ts`](../../../packages/chat-core/src/cache.ts)) and the chapter-config PATCH ([`packages/hooks/src/use-org-config.ts`](../../../packages/hooks/src/use-org-config.ts)), the one opted-in exception inside the package itself. Two writes must stay pessimistic whatever the default becomes: invoice status transitions (`useTransitionInvoiceStatus`) and service approve/reject (`useReviewServiceEntry`) are irreversible, so the UI waits for server confirmation rather than rendering a state it cannot roll back.
- **Billing pay affordance (client gate).** The Pay action renders only when the invoice is `OPEN`, its `user_id` is the signed-in member's, and `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` is configured (absent → the affordance does not render, so local dev, CI, and the build prerender are unaffected). The Stripe Elements dialog confirms against the `client_secret` from `POST /v1/invoices/:id/payment-intent` with `redirect: "if_required"` (3-D Secure stays in-page), then re-reads the invoice until the server reports PAID. List scoping, failure-code mapping, and the webhook-is-truth-for-PAID rule: [`spec/behavior/billing.md`](../../behavior/billing.md) §Member payment flow.
- **Billing subscription card (checkout entry point).** `/billing` renders the subscription card first, because when a chapter is locked it is the only control on the screen that can succeed. It reads `subscription_status` from the chapter payload — the same query the subscription gate uses, never a second source — and renders nothing while that is unresolved, so a slow or failed fetch never asserts a lock. Checkout is offered at `incomplete` and at `canceled`; only `past_due` routes to the Customer Portal, because only it still holds a live subscription a second checkout would duplicate ([`spec/behavior/billing.md`](../../behavior/billing.md) §Duplicate checkout). Stripe returns to `/billing?checkout=success|cancelled`; because the webhook — not the redirect — activates the chapter, `success` polls for the flip on a bounded schedule (10 × 3s) and invalidates both the `["chapters"]` and `["billing"]` caches so the page cannot half-update. The card reads `?checkout=` via `useSearchParams`, so it must stay under a `<Suspense>` boundary. A stale `?checkout=success` never suppresses the recovery control for a chapter that has since lapsed.
- **Slash palette fails closed.** The `cmdk` palette reads its catalog from `@repo/chat-integrations` filtered by `useOrgConfig().isModuleEnabled(requiredModule)`. While the chapter-config query is pending it renders an explicit "Loading commands…" panel; on error, a "Modules unavailable" panel with Retry — never the unfiltered catalog. Empty match → "No matching command."
- **Chat reconnect order (web client).** The client gates REST backfill (`GET /channels/:id/messages?since=<lastSeen>`) on the realtime subscription reaching `SUBSCRIBED` — subscribe first, then backfill — relying on the single idempotent per-channel merge keyed by `client_message_id` to dedupe overlap (`packages/chat-core`, wired through the web glue in `apps/web/lib/chat/`); that merge lands in one normalized cache per channel under query key `["chat", channelId, "messages"]`, shaped `{ byId, order, actionIndex }`. Message-delivery guarantees: [`spec/behavior/chat/README.md`](../../behavior/chat/README.md) and [`../resilience.md`](../resilience.md).
- **The chat composer is never disabled offline.** It takes `isOffline` and renders a label; `sendMessage` writes to the Dexie outbox before it touches the network, so gating it would defeat the queue. This is [`../resilience.md`](../resilience.md) §2's rule, which web broke until the #920 chat slice — `submit()` returned early on the same flag, so Enter discarded the draft silently.
- **Chat unread and mention counts come from `GET /v1/channels/unread`**, read through `useChannelUnreadCounts()` in `@repo/hooks` and never re-derived client-side ([`spec/behavior/chat/README.md`](../../behavior/chat/README.md) § Read Receipts). The channel payload carries no counts; a `unread_count?` field on the web channel type claimed otherwise for a long time and nothing ever populated it, so the badge could not render. Unread is the neutral badge, mention/DM the fixed red — never the chapter accent.
- **Chat drafts & outbox (Dexie).** `drafts(channelId, body, updatedAt)` restore on reload; `outbox(clientId, channelId, body, attempts, queuedAt, status)` flushes in order on reconnect — a 4xx moves the entry to `failed` (surfaced inline with Retry / Discard), network errors and 5xx stay queued.
- **Realtime primitive.** Live surfaces (event attendance rosters, the events list, the notification drawer) subscribe to a **private broadcast change-ping** via the shared `useRealtimeTable` hook ([`apps/web/lib/realtime/use-realtime-table.ts`](../../../apps/web/lib/realtime/use-realtime-table.ts)), and one shared browser Supabase client multiplexes every subscription over a single websocket ([`apps/web/lib/realtime/supabase-realtime.ts`](../../../apps/web/lib/realtime/supabase-realtime.ts)). The hook takes `{table, scopeId}` and builds its topic from the contract in [`change-topics.ts`](../../../apps/web/lib/realtime/change-topics.ts); the ping carries no row data and the hook's whole body is `invalidateQueries`. **Not `postgres_changes`** — those tables are API-enforced and publishing them would move the enforcing layer into RLS (#867).
- **Notification drawer.** Endpoint + realtime contract and the web-push scope decision: [`spec/behavior/notifications.md`](../../behavior/notifications.md).
- **Event role targeting.** `required_role_ids` wire semantics (omit-on-create → `null`; `[]` on update clears; empty ≡ untargeted): [`spec/behavior/events.md`](../../behavior/events.md) §Event Creation.
- **Onboarding wizard.** Trigger, re-trigger signal, and server-side config materialization via `POST /v1/chapters/onboard`: [`spec/behavior/onboarding.md`](../../behavior/onboarding.md). Wizard UI contract: full-screen overlay at [`apps/web/components/onboarding/chapter-wizard.tsx`](../../../apps/web/components/onboarding/chapter-wizard.tsx), is **not** covered by the [375px floor](#responsive-contract) gate — it is an overlay `ChapterWizardGate` mounts conditionally on a zero-membership account, never a route, so neither floor suite can reach it, and this page asserted a floor nothing was measuring until the Profile & pre-auth slice said so — directory combobox debounced 250ms against `GET /v1/chapter-directory/search` with explicit idle/loading/no-results/error states, and a manual-entry path that is always available.
- **Custom roles & fields CRUD.** Endpoint permissions and status-code semantics (400 wildcard capability, 403 core-role delete, 409 duplicate key, `key`/`type` immutability): [`spec/behavior/settings/customization.md`](../../behavior/settings/customization.md).
- **Points audit.** `GET /v1/points/transactions` (`points:view_all`, `limit` clamped 1–200, default 50) and anomaly flagging: [`spec/behavior/points.md`](../../behavior/points.md).
- **Config, theme, archetype.** Config reads/writes go through `GET`/`PATCH /chapters/:id/config` and every write produces an audit row mirrored to `#chapter-audit`; palette saves go through `POST /chapters/:id/theme-palette` (server recompute, applied without reload). The engine persists **hex**, so any token it writes MUST be stored as a complete colour value and read as a bare `var()`, never wrapped in `hsl()` — the wrapper turns an injected `#C49A3A` into the invalid `hsl(#C49A3A)` and the chapter's branding silently does not paint (#1143). Every colour token in both stylesheets — [`packages/theme/src/signet.css`](../../../packages/theme/src/signet.css), which this surface ships, and the legacy [`packages/theme/src/globals.css`](../../../packages/theme/src/globals.css), which `apps/landing` keeps — is stored that way — one format, no per-token pairing rule — owned by [`../design-system/accent-engine.md`](../design-system/accent-engine.md) §6 and not restated here; [`packages/theme/src/tailwind.config.spec.ts`](../../../packages/theme/src/tailwind.config.spec.ts) and [`packages/theme/src/signet.css.spec.ts`](../../../packages/theme/src/signet.css.spec.ts) enforce both halves of it per stylesheet, including a repo-wide ban on hand-written `hsl(var(--token))` (#1151): [`spec/behavior/chapter-config.md`](../../behavior/chapter-config.md). Archetype switching resets modules/role pack/vocabulary and preserves identity, branding, and custom fields: [`spec/behavior/settings/README.md`](../../behavior/settings/README.md).

The **Chapter Ops slice** trued up `components/{events,tasks,study,service,geofences}/**`. Beyond the repaint it settled three things the remaining slices inherit. Status colour is checked by vocabulary rather than by grepping for the accent — #1202 reported one accent-painted badge and the family had five, in three spellings, plus the mirror error of §5's Neutral count badge carrying `LATE`, `PENDING` and `ACTIVE`. And `window.confirm` is a behavioural ban rather than a visual one — its Binds column reads "Every surface" — so the six native dialogs here (four `confirm`, two `prompt`) became [`apps/web/components/shared/confirm-dialog.tsx`](../../../apps/web/components/shared/confirm-dialog.tsx), which the four families still holding native dialogs can adopt rather than redesign. It changed no data contract: the realtime change-ping wiring, the `required_role_ids` semantics, and every §5 gated write are as written above, including the deliberate ungating of study Pause/Resume and Stop, which act on a running session and must never trap a member in a timer they cannot end.

The **Resources & Reporting slice** trued up `components/{documents,backwork,polls,reports}/**` — naming all four directories here because this family's own name reads as three, and `/polls` is filed under Chapter in the nav table above. Beyond the repaint it settled four things. A status vocabulary reached by a derived boolean is still a vocabulary: `/polls` painted `Open` in the chapter accent through an inline ternary and had no mapper for the shared invariant to check, so [`poll-status.ts`](../../../apps/web/components/polls/poll-status.ts) joins the five and `status-kind.test.ts` grew a table for boolean-input mappers. The accent sweep runs in both directions — the same slice took the accent *off* the poll status and left it *on* `/documents`' folder filter, which §5 already called accent-worthy and which had been spelled as a raw `bg-primary/10` wash. A screen's states must not sit above its own dialogs: `/documents` early-returned its loading and error states above the gated upload `Dialog`, so a background refetch failure unmounted an open upload form mid-draft, which is [`../design-system/components.md`](../design-system/components.md) §10's rule met from the other side. And an error state that was never written down is an error state that does not exist — `/reports` caught a failed run, raised a toast, and fell through to its idle copy, because `writing.md` §7's table for it had no Error row. It changed no data contract: the 5,000-row cap, the client-side CSV built from the preview, the signed-URL PDF, and every §5 gated write are as written above.

The **Settings & Roles slice** trued up `components/{settings,roles}/**`. Beyond the repaint it settled four things. A tier is not a status: the modules tab painted `Chapter Pro` in the chapter accent and `Free` in a hand-spelled success tint, and both now take §5's Hairline, because a module's price is a fixed property of the catalog while its *state* is the Switch beside it — a green `Free` next to an off switch said the module was on ([`settings-status.ts`](../../../apps/web/components/settings/settings-status.ts)). The accent sweep ran the other way in the same pass: the archetype grid's selected card was a raw `bg-primary/5` wash of the chapter hex on a selection §5 genuinely calls accent-worthy, and takes the two card-seated states now. A screen's states must sit *inside* its own permission gate — `/roles` early-returned loading and error above `<Can>`, so a member without `roles:manage` was told the roles were loading and then that they had failed, for a surface they were never going to see. And a token that reads like the right one is not a measurement: the capability matrix's missing-permission mark went from a 2.184:1 opacity wash to `--muted`, which is 3.568:1 on that card and under §6, before landing on `--muted-foreground` — `✓` and `—` are characters, so the text floor applies, not the glyph one. It changed no data contract: the `?tab=` deep links, the archetype-switch reset semantics, the wildcard's transfer-only path, and every §5 gated write are as written above.

The **Profile & pre-auth slice** trued up `components/{profile,onboarding}/**`, the four routes outside `(dashboard)` — `/`, `/sign-in`, `/sign-up`, `/join`, `/no-access` — and `app/global-error.tsx`, drawing them in [`apps/web/components/profile/profile-glyphs.tsx`](../../../apps/web/components/profile/profile-glyphs.tsx). It is the last screen family, so with it every `apps/web` surface ships Signet and no in-screen icon is on the Lucide interim pack except the control furniture [`../design-system/iconography.md`](../design-system/iconography.md) §6.2.2 keeps there deliberately.

Four of those screens carried staging-demo copy and three were **rebuilt rather than repainted**, which is the finding rather than a scope note. `/`, `/sign-in`, `/sign-up` and `/join` came from an early milestone chunk — two- and three-card grids whose copy read "Frapp staging", "Sign in to manage your chapter in staging", "This milestone enables real staging usage, not preview data" and "Invite redemption writes directly to the chapter membership table". They are the first thing a member ever sees, and they described the build rather than the product. All five pre-auth routes now share one column, [`apps/web/components/auth/auth-screen.tsx`](../../../apps/web/components/auth/auth-screen.tsx): the layout had been inlined per route, which is how the copy drifted into four voices and four heading sizes without anyone editing a shared file.

Beyond the repaint it settles four things.

**A pre-auth screen has no tenant, so the accent slot holds the house default there — and the mark still may not use it.** `useChapterTheme()` mounts inside [`dashboard-shell.tsx`](../../../apps/web/components/layout/dashboard-shell.tsx) and these routes render outside it, so the engine never runs and the accent family resolves to `signet.css`'s baked seed. Ordinary chrome may take it and does: the primary button, the footer links and the `/no-access` state tile are all accent-role classes, and if a chapter accent were ever applied this high they *should* follow it. The **mark** is the exception, because [`../brand-identity.md`](../brand-identity.md) §2 says it MUST NOT take the chapter accent ever — so [`signet-mark.tsx`](../../../apps/web/components/auth/signet-mark.tsx) takes `--gold-house` explicitly rather than relying on a slot that merely happens to be unfilled. The mirror half is `/profile`: it renders *inside* a chapter, so its s15 identity header takes the accent roles rather than the house family the board happens to draw it in.

**The reference wins on visuals and not on the data model.** s02 draws a six-cell row for a shared chapter code; [`spec/behavior/onboarding.md`](../../behavior/onboarding.md) specifies single-use 24-hour invite tokens, and [`../README.md`](../README.md)'s precedence rule puts behavior above UI on what the product does. So `/join` takes s02's chrome — the back affordance, the title ladder, the primary, the `--surface-1` hint card — and keeps one token field. `apps/mobile/app/(auth)/join.tsx` had already made that call in its own docstring; both surfaces now record it, so neither can drift.

**A control with no reader is deleted, not restyled.** `/profile`'s theme `Select` wrote `user_settings.theme`, which nothing on any surface has read since `next-themes` left in the shell slice — while the account menu paragraph above already asserted the surface had no theme switch. The tutorial slide advertising it went in the same change.

**A second query on a screen is a second set of states.** `/profile` reads `GET /v1/users/me` *and* `GET /v1/settings`, and only the first had any branches. A failed settings fetch rendered empty quiet-hours fields beside a live Save button, and because the submit maps an unloaded field to `undefined`, pressing it sent an empty body and toasted "Preferences saved" — [`spec/behavior`](../../behavior/README.md)'s reads reported as writes. The card carries its own nested states now. The same screen also moved off a bare `isError`: TanStack keeps `data` through a background refetch failure, so the old branch unmounted a form holding unsaved drafts when a window-focus refetch failed.

It changed no data contract: the `/` → `/chat` redirect, the `redirectTo` open-redirect guard and its reuse as the magic-link `emailRedirectTo`, the invite token's 410/409 semantics, and the wizard's cold-path `POST /v1/chapters/onboard` are all as written above.

The **legacy engine cutover** (slice 9) closed the series. It touched no screen — every family was already Signet — and deleted the `derivePalette` accent engine, which had gone on being computed and persisted on every chapter save although nothing had read its output since the shell slice. Its only production caller was `buildChapterPalette` in the API, which now writes one map instead of merging two. Three things about it are worth keeping.

**A stored artifact outlives the code that wrote it.** `chapters.theme_palette` is unconstrained jsonb and no backfill prunes it, so every row saved before the cutover still holds the eight dead legacy keys. Deleting the writer was safe *because* both clients read by allow-list — [`use-chapter-theme.ts`](../../../apps/web/lib/hooks/use-chapter-theme.ts) takes a fixed `--signet-*` list, mobile takes one key — and those allow-lists are therefore load-bearing rather than historical. The guard asserting no legacy token reaches `:root` outlived its subject for the same reason.

**A documented blocker can be wrong about its own subject.** [`../design-system/accent-engine.md`](../design-system/accent-engine.md) §6 gated this deletion on "mobile's pre-Signet-map fallback retiring". That fallback is `resolveChapterAccentColor`, a different function in a different package that re-validates `accent_color` and never read the deleted engine's map — `apps/mobile` does not even declare `@repo/chapter-theme`. The two were coupled in prose only, and the same §6 said elsewhere that the legacy units die "at the end of the #920 series". Read the code the blocker names before treating it as a gate.

**A chapter now supplies one colour, not two.** `branding.colors.dark` fed only the deleted map, so it went with it — DTO, Zod schema, regenerated contract, and the "Primary (dark) color" picker in both onboarding wizards. The neutral ladder was already fixed rather than branded ([`../design-system/accent-engine.md`](../design-system/accent-engine.md) §5), so there was nothing left for a second colour to paint; #541, which tracked building a picker for it, is obsolete.
