Grid and rhythm

Swiss hierarchy comes from the grid and hairlines, not from boxes. The canvas guides on both page boards draw it.

Desktop 1440

12 columns · 80 margin · 24 gutter. Copy spans 4 to 7 columns; frames span 5 to 8. Sections start 96 apart.

Phone 390

4 columns · 20 margin · 16 gutter. One column of content; frames sit at 350 wide. Sections start 64 apart. 390 is the Design type's phone size and iPhone 15 logical width; the brief's 375 is the older iPhone SE width.

Spacing

4px grid, foundations.md §9. 24 between components, 16 inside a stack, 12 in a list row, 8 between a title and its line. Landing chrome is on the 4px grid; frame internals follow the reference boards.

Motion, decided

The full spec, with running demos, is the Motion sheet. foundations.md §11 locks no motion tokens; README §7 locks the discipline: no entrance on hero text or the primary CTA, once-only below-fold reveals, hover is colour and border only, 300ms ceiling below the fold. Three concepts were drafted, judged and attacked by two skeptics; what survived is below. Verified: no motion library in any package.json; the landing's client code is TrackedCta, PageviewTracker and global-error.

The signature moment

Ships

Once per load: the crest wipes in along its own diagonal (520ms), settles 10px (640ms), a warm field rises behind it and holds (660ms), and the column rule draws (300ms). CSS only, motion-safe only. The H1, lead and CTA never move.

Cost: a fourth motion class written into README §7 and foundations §11. Runs on the two page boards right now.

Reveal on view, once

Section hairlines draw in, officer and pricing cards fade up 8px with a 60ms stagger, the chat thread arrives row by row. A 22-line client wrapper adds one class when a block first enters view, so every reveal plays once and never runs backwards; the base state is the finished page.

Cost: apps/landing goes from three client files to four. Scroll-scrubbed view() timelines were considered and cut: they replay on every direction change, which breaks README §7's once-only row.

Chrome answers the hand

Hover and focus transition colour and border in 220ms; the focus ring fades in at 140ms. The Pro card warms its border and steps one rung up the ladder on hover or focus-within. No scale, no shadow, no translate on any control.

Cut entirely: every infinite loop (a breathing light, a drifting crest, a pulsing status dot), any keyframe on a semantic red, amber or green, and any beat that asserts product behaviour (counts ticking, typing dots). Those last two are post-launch candidates behind the same wrapper.
